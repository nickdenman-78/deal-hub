# ADR-0010 — Persistence conventions (PostgreSQL + EF Core)

**Status:** Accepted

One **PostgreSQL** database. Each module owns a **schema**, its own EF Core `DbContext` and its own
migrations (with the migrations history table in the module's schema). No cross-module joins or foreign
keys; a module never reads another's tables. Modules whose aggregates are event sourced keep their event
streams in Marten ([ADR-0013](./0013-event-sourcing-with-marten.md)); everything here applies to the EF
Core side.

## PostgreSQL specifics

- **snake_case** names via `UseSnakeCaseNamingConvention()` (EFCore.NamingConventions) — tables, columns,
  keys and indexes. C# keeps PascalCase.
- **`NpgsqlDataSource` is registered once** (Aspire `AddNpgsqlDataSource` / `AddNpgsqlDbContext`) and
  shared by EF Core, Dapper, Wolverine and Marten.
- **`jsonb`** for semi-structured payloads; never for data a query filters on.
- **No system-versioned temporal tables.** History is provided by event sourcing for Deals and Settlement,
  and by an explicit append-only amendment table where an EF Core aggregate needs one. Triggers are not used.
- `timestamptz` for every instant (stored UTC); market-local dates (`DateOnly`, AEST trading days) are
  stored as `date`, never as midnight timestamps.

## Ids

Entity and aggregate ids are **Guid v7**, generated by the domain at creation
([ADR-0014](./0014-guid-v7-ids-and-business-references.md)). The store never allocates keys, so children
can be referenced by id immediately and messages can carry ids before commit.

## Repositories reconcile children by id

A repository updates child collections by matching ids — insert new, update existing, delete missing. It
never clears and rebuilds a collection: that re-keys every row and strands whatever points at them.

## Internal entities are separate from domain types

- Persistence rows are `Db` + entity name, singular (`DbTrade`), one per file. Domain types never take the
  prefix.
- One `IEntityTypeConfiguration` per entity, named `{Entity}Map`, under the context's
  `Persistence/Configuration`. `OnModelCreating` sets the default schema and calls
  `modelBuilder.ApplyAllConfigurations<TContext>()`. Maps are discovered **by namespace**.
- Where the domain type maps cleanly (owned value objects, converters), mapping the domain type directly is
  allowed; the `Db*` row exists when the persistence shape genuinely differs.

## Enums are stored as their member name

`ConfigureConventions` applies `Properties<Enum>().HaveConversion<string>().HaveMaxLength(64)`. The stored
text is the `*Value` enum member name (`PeakLoad`), never the enumeration's display name.

## Every column has an explicit order

Either every column carries `HasColumnOrder` or the ordering means nothing (EF sorts unordered columns
first). Key = 1, the rest in tens, audit columns in the 9900s. Table-per-hierarchy trees give each level its
own band (root 1–100 with the shadow discriminator at 100, then a hundred per branch from 1000 up).

## Hierarchies mirror the domain

A TPH tree names only its root for the table; subtypes are named for the domain subtype they map, which is
also the discriminator value. Each branch declares its own columns. The discriminator is shadow state.

## Auditing and soft delete

`DbContextBase` stamps `IAudited` (created/modified by and at) and converts deletes into flags for
`ISoftDelete`. **`ISoftDelete` needs a global query filter before any entity adopts it.**

## Reads

Query handlers default to **EF Core no-tracking projections** (`AsNoTracking().Select(...)`) straight into
response DTOs. **Dapper over the shared `NpgsqlDataSource`** is allowed for reporting, risk and other
set-based queries where hand-written SQL is clearer or materially faster; such SQL stays inside the owning
module's schema.

## Migrations

`Persistence/Migrations` is EF-generated and never hand-edited. Migrations are applied at startup in
Development only (the AppHost database starts empty); other environments run them as an explicit pipeline
step. Wolverine's and Marten's own tables are created by those libraries in their own schemas.
