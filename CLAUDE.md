# CLAUDE.md

This file provides guidance to Claude Code when working with code in this repository.

## What this is

**ETS** — an energy trading system for participants in the Australian National Electricity Market (NEM).
It captures deals in **ASX electricity futures** (base, peak and $300 cap futures, strips and options) and
**OTC derivatives** (swaps, caps, options), and supports middle and back office through **Settlement** and
**Risk** modules.

It is a **.NET 10 modular monolith** built **model first**: the domain is designed in Context Mapper
(`modelling/ddd/**/*.cml`) and the C# domain code is a reflection of that model.

**Platform stack** (each line has an ADR in `docs/architecture/adr/`):

| Concern | Choice |
|---|---|
| Database / ORM | PostgreSQL, schema per module; EF Core (snake_case); Dapper allowed for heavy reads (0010) |
| Event sourcing | Marten for Deals and Settlement aggregates (0013) |
| In-process CQRS | ETS kernel `ICommand`/`IQuery` handlers + Scrutor decorators — **no MediatR** (0008) |
| Messaging | Wolverine over RabbitMQ for all module-to-module traffic; transactional outbox + durable inbox in PostgreSQL — **no MassTransit** (0011) |
| Caching | FusionCache (L1 memory + Redis L2 + Redis backplane) behind `HybridCache` (0012) |
| Identity / authz | Keycloak JWTs; permissions owned by the Users module, one declared policy per permission (0006) |
| Ids | Guid v7 generated by the domain + human-readable business references (0014) |
| Scheduling | Quartz.NET (PostgreSQL job store, holiday calendars) sending Wolverine commands (0015) |
| Observability | Serilog → Seq; OpenTelemetry → Aspire dashboard + Seq; `/alive` and `/health` (0016) |
| Orchestration | .NET Aspire: PostgreSQL, Redis, RabbitMQ, Keycloak, Seq (0007) |
| Tests | xUnit v3, Shouldly, Bogus, Testcontainers, ArchUnitNET (0017, 0018) |
| Frontend | Vue 3 + TypeScript + Vite SPA in a pnpm workspace; `@ets/ui` on `@vuetify/v0`; Keycloak via `oidc-client-ts` |

## Package & build conventions

- **Central Package Management.** Every NuGet version lives in `Directory.Packages.props`. A `.csproj` uses
  `<PackageReference Include="..."/>` with **no `Version`**; add the version centrally first. Per-project
  `VersionOverride` is disabled. MSBuild SDK versions (the Aspire AppHost SDK) live in `global.json`
  `msbuild-sdks`. Keep the .NET 10 packages (ASP.NET Core, EF Core, `Microsoft.Extensions.*`) on one patch
  line — under transitive pinning a stray older patch fails restore with NU1109.
- **Global props** (`Directory.Build.props`) give every project `net10.0`, nullable, implicit usings,
  `JetBrains.Annotations`, `SonarAnalyzer.CSharp` and `coverlet.collector`. SDK pinned in `global.json`.
- Mark DI/reflection-only members `[UsedImplicitly]` to silence "unused" analyzer warnings.
- **C# house style** (`.editorconfig` + `ets.sln.DotSettings`, applied with Rider cleanup): block-bodied
  methods, **no trailing commas**, StyleCop member ordering, alphabetical field ordering, ~120-column wrapping,
  no redundant named arguments, self-closing tags as `<Tag/>`.
- **Tests are xUnit v3** (`<OutputType>Exe</OutputType>`, set in `tests/Directory.Build.props`) with
  **Shouldly** (never FluentAssertions — commercial from v8). `TheoryData<>` + `[MemberData]` for data-driven
  cases. Test names use underscores: `Confirm_Fails_WhenDealIsCancelled`. Assert on the returned `Result`.
  Integration tests use Testcontainers (PostgreSQL, Redis, RabbitMQ, Keycloak) and Wolverine tracked
  sessions — never sleeps.

## Shared kernel conventions (`src/core/`)

These patterns are non-obvious and span many files. The contract is in
[`docs/architecture/kernel.md`](docs/architecture/kernel.md).

- **Result pattern, not exceptions.** Domain behaviour and handlers return `Result` / `Result<T>`;
  a business-rule failure is `Result.Failure(DomainError.*)`, never a `throw`. `Result<T>` converts
  implicitly from `T?` (null → failure).
- **Custom CQRS, no MediatR.** Commands implement `ICommand` / `ICommand<T>`, queries `IQuery<T>`, handlers
  the matching `I*Handler`. A module registers its handlers with `services.AddMediator(assembly)`; the
  **host** calls `services.AddMediatorPipeline()` **once, after every module** (validation + logging
  decorators — [ADR-0008](docs/architecture/adr/0008-cqrs-decorators-registered-once.md)). There is no
  dispatcher: endpoints inject the closed `IQueryHandler<,>` / `ICommandHandler<,>`.
- **Enumeration value objects, not C# enums.** Domain enumerations derive from `Enumeration<TValue, TEnum>`
  (abstract record, nested `sealed record` members, rich properties), each paired with a plain `*Value` enum
  for storage. Resolve with `FromValue()` / `FromName()` / `TryParse()`.
- **Guid v7 ids, generated by the domain.** Strongly typed id records (`DealId(Guid Value)`) created through
  `IIdGenerator` at the moment an entity is created. People-facing **business references**
  (`DealReference`, Base30 + Luhn) are allocated by an Infrastructure port — never derived from the Guid,
  and a reference prefix/base is never changed once issued ([ADR-0014](docs/architecture/adr/0014-guid-v7-ids-and-business-references.md)).
- **Domain events are raised by aggregates** (past tense, in Domain) and stay inside the module. The module's
  unit of work maps the relevant ones to versioned **integration events** and publishes them through the
  Wolverine outbox in the same transaction. Event-sourced aggregates' events *are* their state
  ([ADR-0013](docs/architecture/adr/0013-event-sourcing-with-marten.md)).
- **Time via `IDateTimeProvider`.** Never `DateTime.Now` / `UtcNow` in domain or application code.
- **Money and energy are value objects.** `decimal` underneath, explicit units (`$/MWh`, `MWh`, `MW`),
  rounding only at boundaries. Reuse the kernel's `Money`, `Price`, `Volume`, `Percent`, `Factor` types.

## Modules and the host (`src/modules/`, `src/hosts/`)

- **A module is five csprojs**: `Ets.Modules.{Module}.{Domain,Application,Infrastructure,IntegrationEvents,Presentation}`
  with a fixed reference graph — `Application → Domain`; `Infrastructure → Application, IntegrationEvents`;
  `Presentation → Application`. **`Application → Infrastructure`, `Presentation → Infrastructure` and
  `Infrastructure → Presentation` are forbidden**, enforced by `tests/architecture/EtsArchitectureTests`
  ([ADR-0001](docs/architecture/adr/0001-layered-csprojs-per-module.md)).
- **`IntegrationEvents` is the module's public API** — the only project another module or the host may
  reference. It stays reference-light (ideally none). Integration event contracts (versioned records),
  read-side snapshots, permission names and configuration contracts go there
  ([ADR-0004](docs/architecture/adr/0004-integration-events-as-public-api.md)).
- **A module never reads another module's tables.** Cross-module reads go through a local read model;
  cross-module writes go through integration events. Deals → Settlement → Risk is the natural flow.
- **The host references Infrastructure, Presentation and IntegrationEvents per module** — never a module's
  Application or Domain.
- **Three lines per module in `Program.cs`:** `Add{Module}Module(configuration)` (Infrastructure — services),
  `Add{Module}Endpoints(policies)` (Presentation — endpoint registrations) and `app.Map{Module}Module()`
  (Presentation — routes). No `IModule`, no discovery
  ([ADR-0003](docs/architecture/adr/0003-module-composition-root-split-in-two.md)).
- **Endpoints are one `internal sealed class : IEndpoint` per slice**, discovered by `AddEndpoints(assembly)`
  and mapped into the module's own `MapGroup` by `MapEndpoints(fromAssembly)`. They are resolved from the
  **root** provider, so they **must have a parameterless constructor**; per-request services are injected
  into the route delegate ([ADR-0002](docs/architecture/adr/0002-endpoints-discovered-by-di.md)).
- **Each endpoint states its own authorization policy.** The module's route group carries none, so a new
  write route cannot inherit read authorization. Policies are **permissions** (`deals:confirm`) declared in
  each module's `{Module}Permissions` (IntegrationEvents); the host registers one policy per declared
  permission — never a dynamic policy provider. Keycloak authenticates; the Users module supplies permission
  claims via a cached claims transformation. There is no switch that disables authorization
  ([ADR-0006](docs/architecture/adr/0006-keycloak-with-permission-based-authorization.md)).
- **Messaging (Wolverine).** Integration events are plain versioned records in the producer's
  IntegrationEvents. Consumers are Wolverine handlers in the **consuming module's Infrastructure** that
  translate the event into the module's own command and call the kernel handler. **Domain and Application
  never reference Wolverine.** Wolverine conventional handler discovery is disabled — kernel handlers also
  end in `Handler` ([ADR-0011](docs/architecture/adr/0011-messaging-with-wolverine-and-rabbitmq.md)).
- **Caching** goes through `HybridCache` (FusionCache underneath). Keys are module-namespaced constants;
  fail-safe/stale limits are declared per entry type; never cache aggregates or serve cached state to a write
  path ([ADR-0012](docs/architecture/adr/0012-caching-with-fusioncache-and-redis.md)).
- **Scheduled work** is a thin Quartz job in the module's Infrastructure that sends a Wolverine command carrying
  its business date ([ADR-0015](docs/architecture/adr/0015-scheduling-with-quartz.md)).
- **One OpenAPI document per module**, each pinned with `ShouldInclude` to its own group name, so a route is
  published only into the document it names. Every document registered must also be named to
  `MapScalarApiReference`.
- **Configuration is a named section per adapter**, bound to an options class that declares
  `public const string SectionName`, validated with `.Validate(...).ValidateOnStart()`. No per-module config
  files ([ADR-0005](docs/architecture/adr/0005-module-configuration-sections-not-files.md)).
- **Adding a module:** create the five csprojs, add `AssemblyReference.cs` to each, wire the reference graph,
  add `{Module}Module.cs` (Infrastructure), `{Module}Endpoints.cs` + `OpenApiDocuments.cs` + `Tags.cs`
  (Presentation), `{Module}Permissions.cs` (IntegrationEvents), add the three lines to `Program.cs`, include
  its Infrastructure assembly in Wolverine discovery and enrol its DbContext (or Marten store) for the outbox,
  register its OpenAPI document, and add the module to the architecture tests' module list.

## Persistence conventions

See [ADR-0010](docs/architecture/adr/0010-persistence-conventions.md) for the reasoning.

- **PostgreSQL, one schema per module.** EF Core `DbContext` per module deriving from the kernel's
  `DbContextBase` (stamps `IAudited`, converts deletes to flags for `ISoftDelete`), `UseSnakeCaseNamingConvention()`,
  migrations history table in the module's schema. `Persistence/Migrations` is EF-generated, never hand-edited.
- **Deals and Settlement are event sourced in Marten** (an ancillary store per module, own schema); every
  other module uses EF Core. Never mix both for one aggregate.
- **No temporal tables** (PostgreSQL has none): history comes from event streams, or an explicit append-only
  amendment table.
- **Reads:** EF Core `AsNoTracking()` projections by default; Dapper over the shared `NpgsqlDataSource` for
  reporting/risk queries, inside the module's own schema.
- **Internal EF entities are `Db` + entity name** (`DbTrade`) when the persistence shape differs from the
  domain type. **One `IEntityTypeConfiguration` per entity**, named `{Entity}Map`, under the context's
  `Persistence/Configuration`; `OnModelCreating` sets the schema and calls `ApplyAllConfigurations<TContext>()`.
  Maps are discovered by namespace.
- **Enums are stored as their member name, never an ordinal** — a convention on the context, not per property.
- **Every column has an explicit `HasColumnOrder`**: key 1, the rest in tens, audit columns in the 9900s.
- **Table-per-hierarchy mirrors the domain hierarchy**; the discriminator is shadow state.
- **Repositories reconcile child collections by id**; never clear-and-rebuild (it re-keys every row).
- **`ISoftDelete` needs a global query filter before any entity adopts it.**

## Model-first DDD

- **The CML is the source of truth.** When CML and C# disagree, the CML wins — update the C#, or ask before
  changing the CML. Use the `ddd` skill to translate.
- **Every new domain term goes into the owning context's `ubiquitous.md` in the same change.** Shared-kernel
  terms (`modelling/ddd/shared/ubiquitous.md`) must be genuinely cross-context.
- **Aggregates guard their invariants**: state changes go through the root's methods, no public setters, no
  anemic models, no `*Manager` / `*Helper` services that reach in and mutate. Domain events are past tense.
- Before implementing a domain change, state briefly: which building blocks and layers are affected, the
  aggregate boundary and invariants (in ubiquitous language), and the CML elements it reflects. If the
  aggregate boundary or intended behaviour is unclear, ask rather than guess.

## Frontend conventions (`src/clients/`)

**Read [`src/clients/CONTEXT.md`](src/clients/CONTEXT.md) before adding a package or changing how styles are
shared.** The essentials:

- **Layout.** `apps/*` are deployables named `@ets/app-*`; `packages/*` are shared, never deployed, and
  `"private": true`. `@ets/brand`, `@ets/ui`, `@ets/editor`, `@ets/tsconfig`, `@ets/eslint-config` were copied
  from retail-systems' `@retail/*` and are now owned here — no sync back.
- **Raw-source packages.** Shared packages have no build; apps consume `.ts`/`.vue`/`.css` through the
  `exports` map. A new runtime dependency of a shared package must be added to each app's
  `optimizeDeps.include` in the `'@ets/ui > dep'` form, or Vite discovers it late and reloads the page.
- **Versions.** Anything that must agree across packages goes in the `catalog:` of `pnpm-workspace.yaml`
  (consumers write `"vue": "catalog:"`). The lockfile was seeded from retail's tested set — upgrade
  deliberately, never by deleting `pnpm-lock.yaml`. New install scripts must be approved in
  `onlyBuiltDependencies`.
- **`@ets/ui` admits no domain vocabulary.** Nothing in it knows what a deal or settlement is; domain
  components live in the app.
- **Auth.** Keycloak authorization code + PKCE (`oidc-client-ts`, public client `ets-web`). Permissions come
  from `GET /api/me`, never from decoding the token. Route `meta.permission` and `session.can()` are UX only —
  every endpoint still enforces its own permission. Keep `src/lib/permissions.ts` in step with the modules'
  `*Permissions.cs` catalogues.
- **Module screens** live in `apps/ets/src/modules/{module}/`. ESLint forbids one module importing another;
  cross-module data goes through the API (ADR-0004).
- **Style.** Vue 3 `<script setup lang="ts">`, strict TypeScript. Prettier owns formatting (120 columns,
  single quotes, semicolons, trailing commas, LF); ESLint owns correctness. Note this differs from the C#
  style (which has no trailing commas). Tests are Vitest + `@vue/test-utils` with jsdom, next to the code
  (`*.test.ts`).

## Documentation rules

- **Keep docs in lockstep.** Changing module structure, host composition or the auth model means updating
  `docs/architecture/architecture.md`, `src/CONTEXT.md` and the ADRs in the same change.
- **Design docs record decisions, not progress.** `docs/**`, `CONTEXT.md` and ADRs explain *why*: the problem,
  the options, the decision, the rule that follows. No status, plans, phases or checklists. When a decision
  changes, rewrite it in place — except ADRs, which are dated records: supersede with a new ADR.
- **Deliberate limits are design; unfinished work is not.** A boundary ("X is not enforced because …") belongs
  in the design doc. A gap belongs in `src/CONTEXT.md` under **Known gaps**, phrased as the current shape
  ("X has a handler but no route"), never as a plan.
