# Model-first DDD: CML → C#

The CML files under `modelling/ddd/` are the **source of truth** for the domain model. Generated C# is a
reflection of them. When the CML and C# disagree, the CML wins — update the C# to match, or ask before
changing the CML.

## When to use this skill

- A domain change is requested ("add a cap premium", "a swap can be novated") — model it first.
- Translating a CML `BoundedContext`, `Aggregate`, `Entity`, `ValueObject`, `enum`, `DomainEvent`,
  command or domain service into C#.
- Scaffolding a new module from a bounded context.
- Reviewing whether existing C# still matches the CML (drift check).

## Workflow

1. **Model first.** If the behaviour or structure is not in the CML yet, add it there before writing C#:
   the element in the owning context's CML file, and every new term in that context's `ubiquitous.md`.
   Show the CML change to the user before generating code when it changes an aggregate boundary,
   a lifecycle, or a context relationship.
2. **Read the CML.** Load the relevant `modelling/ddd/**/*.cml`, following `import`s. The `ContextMap`
   gives relationships: `[SK]<->[SK]` = shared kernel; `[D,ACL]<-[U,OHS,PL]` = downstream consuming the
   upstream's published language through an anti-corruption layer.
3. **Resolve the target module.** Use the bounded-context table in `references/mapping.md`. Shared-kernel
   elements go to `src/core/Ets.Core.Domain`. The module folder is **not** derived from the context name —
   read the table; if a context is not in it, ask and then add the row.
4. **Generate per building block** from `references/templates.md`: aggregate root → `AggregateRoot`;
   entity → `Entity`; value object → `record : IValueObject` or `Enumeration<>`; enum → `Enumeration<>` +
   paired `*Value` enum; command → `ICommand` + handler returning `Result` + `AbstractValidator`.
5. **Honour the invariants below.** They are non-negotiable and differ from generic DDD samples.
6. **Test.** Cover aggregate rules and state transitions (including illegal ones), value-object equality,
   handler orchestration and validation. Assert on the returned `Result`.
7. **Build and run.** `dotnet build` on the module project (analyzers run in the build — fix warnings),
   the module's tests, then `tests/architecture/EtsArchitectureTests`.

Before implementing, state briefly: the building blocks and layers affected, the aggregate boundary and
invariants in ubiquitous language, and the CML elements the change reflects.

## Non-negotiable invariants

- **Result, not exceptions.** Domain behaviour and handlers return `Result` / `Result<T>` and
  `Result.Failure(DomainError.*)`. Never `throw` for a business-rule violation. (Throwing is reserved for
  programming errors — an unmapped enum case, a null argument.)
- **Base classes and markers.** Aggregate roots derive from `AggregateRoot` (`IAggregateRoot`); entities
  from `Entity` (`IEntity`); value objects implement `IValueObject` (records) or derive from
  `Enumeration<TValue,TEnum>`. These live in `src/core/Ets.Core.Domain/Models/`.
- **Enumeration value objects, not C# enums.** A CML `enum` becomes an `Enumeration<TValue,TEnum>` abstract
  record with nested `sealed record` members **plus** a paired plain `*Value` enum (`None = 0`) for storage.
- **Guid v7 ids, generated by the domain.** Each aggregate/entity has a typed id record
  (`readonly record struct DealId(Guid Value)`), created via `IIdGenerator` when the entity is created —
  never by the store. People-facing **business references** (`DealReference`) are a separate value object
  allocated by an Infrastructure port; never derive them from the Guid.
- **Associations inside an aggregate are typed ids, not object references** (`SwapLegId`), except
  containment: a child the CML nests in its parent lives in the parent's collection. References to other
  aggregates or modules are always ids.
- **Event-sourced modules (Deals, Settlement).** Aggregates derive from `EventSourcedAggregate<TId>`:
  behaviour validates, returns `Result`, and **raises** past-tense events; state changes only in
  `Apply(TEvent)` methods. Events are immutable, versioned records — never change a released event; add a
  new type. EF Core modules use `AggregateRoot<TId>` and raise domain events the same way.
- **No infrastructure in Domain or Application** — no Wolverine, Marten, EF Core, Npgsql, FusionCache or
  Quartz types. Integration events are mapped from domain events in Infrastructure.
- **CML `extends` becomes C# inheritance.** Intermediate levels `abstract`, leaves `sealed`; never flatten
  into one class with a discriminator property. The root's `Add*` factory switches on the `*Value` enum to
  pick the subtype.
- **Collections** are `IReadOnlyList<T>` over a private `List<T>`, mutated only by intention-revealing
  methods returning `Result`. No public setters.
- **Lifecycles.** A CML `enum` marked `aggregateLifecycle` drives the aggregate's state machine: legal
  transitions are methods on the root; illegal ones return `Result.Failure(DomainError.Conflict(...))`.
- **Commands carry the aggregate root's id** plus the child ids they address. The handler loads through
  the repository, calls **one** aggregate method, propagates its failure untouched, and saves.
- **Validators are shape-only** (required ids, non-empty strings, positive quantities). Business rules
  stay in the aggregate — never re-implement them in a validator.
- **Custom CQRS.** `ICommand` / `ICommand<T>` / `IQuery<T>` with matching `I*Handler` returning
  `Task<Result>` / `Task<Result<T>>`; registered by `services.AddMediator(assembly)`. No MediatR.
- **Time via `IDateTimeProvider`.** Never `DateTime.Now` / `UtcNow`. Domain events implement
  `IDomainEvent`, are named in the past tense, and carry `OccurredAt` supplied by the caller.
- **Money, prices and energy as value objects** with explicit units; `decimal` underneath; round only at
  boundaries.
- **Central Package Management** — versions in `Directory.Packages.props`; `<PackageReference>` has no
  `Version`. DI/reflection-only members get `[UsedImplicitly]`.
