# DDD & .NET rules

The CML under `modelling/ddd/` is the source of truth for the domain; C# reflects it. For any domain
change use the **`ddd` skill** (`.claude/skills/ddd/`).

## Before implementing

State briefly (proportional to the change): the building blocks and layers affected
(Domain / Application / Infrastructure / Presentation / IntegrationEvents), the aggregate boundary and
invariants in ubiquitous language, and the CML elements reflected. If the aggregate boundary or intended
behaviour is unclear, ask rather than guess.

## Layer responsibilities

- **Domain** — aggregates, entities, value objects, domain events, repository ports. Rich behaviour lives
  here, not in application services. No reference to EF Core or ASP.NET Core.
- **Application** — command/query handlers orchestrating aggregates, validators, application ports, DTOs.
- **Infrastructure** — repository implementations, external adapters (ASX, AEMO, market data), event
  mapping and dispatch, the service-side composition root.
- **Presentation** — one `internal sealed` `IEndpoint` per slice with a parameterless constructor, the
  route-side composition root, OpenAPI document and tags.
- **IntegrationEvents** — the module's public API. Reference-light.

Never add `Application → Infrastructure`, `Presentation → Infrastructure`, `Infrastructure → Presentation`,
or any reference to another module's internals.

## Conventions that override generic samples

- `Result` / `Result<T>` and `Result.Failure(DomainError.*)` — never throw for business-rule failures.
- `AggregateRoot` / `Entity` / `IValueObject` records / `Enumeration<TValue,TEnum>` + `*Value` enum.
- Typed Guid v7 ids from `IIdGenerator`, generated by the domain; human-readable `BusinessReference`s
  allocated by an Infrastructure port.
- Deals and Settlement aggregates are event sourced (`EventSourcedAggregate<TId>`, `Apply` methods,
  versioned past-tense events); other modules use `AggregateRoot<TId>` with EF Core.
- No Wolverine, Marten, EF Core, Npgsql, FusionCache or Quartz types in Domain or Application. Wolverine
  consumers live in the consuming module's `Infrastructure/Messaging` and call that module's own command.
- Endpoints require **permissions** (`deals:confirm`) declared in `{Module}Permissions`.
- Caching through `HybridCache` only, with module-namespaced key constants; never cache aggregates.
- Custom CQRS (`ICommand`, `IQuery<T>`, `I*Handler`), registered with `AddMediator`; validation in an
  `AbstractValidator<T>` beside the command, shape-only.
- `IDateTimeProvider`, never `DateTime.Now` / `UtcNow`.
- `decimal`-backed value objects for money, prices ($/MWh), volume (MWh) and capacity (MW); preserve
  precision through calculations and round explicitly at boundaries.
- `async`/`await` for I/O with `.ConfigureAwait(false)`; constructor injection; modern C# (records, pattern
  matching, collection expressions).
- Central Package Management: no `Version` on `<PackageReference>`. `[UsedImplicitly]` on
  DI/reflection-only members.

## Testing

- xUnit v3 + Shouldly (never FluentAssertions); `TheoryData<>` + `[MemberData]`; Bogus for test data.
- Integration tests: Testcontainers (PostgreSQL, Redis, RabbitMQ, Keycloak) + Wolverine tracked sessions;
  never `Task.Delay`.
- Event-sourced aggregates: given events → when command → then events/result.
- Names with underscores: `Confirm_Fails_WhenDealIsCancelled`, `AddLeg_Rejects_OverlappingTerm`.
- Cover aggregate rules and state transitions (legal and illegal), value-object equality and immutability,
  handler orchestration and validation. Assert on the returned `Result`.

## Build

No separate lint step: analyzers run in `dotnet build` (`EnforceCodeStyleInBuild=true`). Keep it
warning-clean. House style: block-bodied members, no trailing commas, StyleCop member ordering,
alphabetical fields, ~120 columns, `<Tag/>`.
